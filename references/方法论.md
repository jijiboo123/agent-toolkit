# 方法论：让 AI 改代码的过程可观察、可验证

## 核心原则

**改之前让人知道动哪里，改之后让人能自己验证。**

AI 改代码最大的问题不是不会写，而是人失去了对代码的掌控感：不知道改了什么、不知道有没有改坏、不知道能不能回退。

## 标准流程

### 第 1 步：跳转

```bash
python scripts/jump.py 目标文件:行号
```

先说清"我要改 XX 文件的第 N 行，改什么"，再动手。

### 第 2 步：改

- **≤60 行**：`type_write.py` 逐字写，`--delay 0.03`
- **>60 行**：分段写，每段写完停 1 秒、打印中文步骤标记（`[第 1 段] ...`）

为什么分界是 60 行：827 字符约 10 秒，人还能盯着看；超过这个量，等待感就大于观看价值了。

### 第 3 步：再跳转

改完跳到新代码的位置，让"改动落点"和"改动结果"在同一个视觉位置。

### 第 4 步：语法检查

```bash
node --check app.js
python -m py_compile main.py
```

这一步几乎零成本，却能挡掉一半的低级错误。

### 第 5 步：功能验证

- 前端：`jsdom_harness`（点击、输入、断言）
- 后端：真实请求 + 状态码 + 响应片段
- 数据：跑一遍并对比预期值

### 第 6 步：贴结果

把**实际输出**贴出来，而不是说"应该没问题"。

## 常见坑

### 1. 用 textContent 判断可见性 → 误报

`textContent` 会把 `hidden` 元素的文字也算进去。判断"加载完成还是错误态"必须看属性：

```js
// ✗ 错：可能同时命中错误提示和正常内容
const isLoading = bodyText.includes('正在加载');

// ✓ 对：看 hidden 属性
const isLoading = !doc.getElementById('loading').hasAttribute('hidden');
```

### 2. 交互事件选错

- 按钮是 `<button data-unit="imperial">`，不是 `#tempUnit`（那是显示用的 span）
- 表单搜索绑在 `submit` 上，只派发 `input` 不会触发
- 结论：**测之前先读绑定代码**，别凭想象派发事件

### 3. 管道传中文变问号

PowerShell 往原生程序传中文，必须显式设：

```powershell
$OutputEncoding = New-Object System.Text.UTF8Encoding($false)
$env:PYTHONIOENCODING = 'utf-8'
```

### 4. 逐字写入的中间态是坏文件

逐字写一半时文件语法不完整（实测 `py_compile` 报 `SyntaxError`）。这是本质，不是 bug：

- 中断会留下半截文件 → 改前先备份
- 编辑器会飘红 → 正常，写完就好

### 5. 环境差异

- 沙箱里没有浏览器 → 用 jsdom
- 沙箱里 `curl`/`Invoke-WebRequest` 可能因证书库受限失败 → 需要更宽权限
- 无头浏览器可能起不来（进程直接退）→ 别在这上面浪费时间，换 jsdom
