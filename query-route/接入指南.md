# 商业火车票 API 接入指南

> 目标：给「查询路线」接上真实的火车票数据，做到**任意站点、任意日期、不用跳转**直接查。

## 先说清楚：这一步必须你自己做

我能把代码和配置槽准备好，但**注册、实名认证、付款这三件事必须你本人操作**——接口商要手机号/身份证验证，要绑支付方式，我无法也不应该代你完成。

## 第 1 步：找供应商

在下面这些平台搜「**火车票**」「**列车时刻**」「**12306**」：

- 聚合数据（juhe.cn）
- 阿里云云市场（market.aliyun.com）
- 极速数据（jisuapi.com）
- 天行数据（tianapi.com）

> 具体哪家有货、叫什么名字，以你搜到的为准。我不写死某一家，因为这类商品上下架很频繁。

## 第 2 步：买之前核对这 5 项（避免白花钱）

| 要确认的 | 为什么 |
|---|---|
| **有免费试用/试调次数** | 先测通再充值，别直接买包年 |
| 支持**站站查询**（不是只查单列车次） | 你要的是"武汉→上海"这种 |
| 返回字段含**车次、出发站、到达站、出发时刻、到达时刻、历时** | 这几个字段缺一个，程序就串不起来 |
| 有**QPS 上限**说明 | 个人用 1-5 QPS 足够，别买大套餐 |
| 计费方式是**按次**还是**包月** | 你只是自己查，按次更划算 |

## 第 3 步：拿到 Key，填进配置

1. 程序里点「车次库」→「**打开 API 配置**」（会自动生成并在记事本打开 `api_config.json`）
2. 按供应商文档填这 5 个关键字段：

```json
{
  "enabled": true,
  "provider": "你买的平台名",
  "method": "GET",
  "url": "供应商给你的接口地址",
  "key": "供应商给你的 key",
  "params": {
    "depart": "{from}",
    "arrive": "{to}",
    "date": "{date}"
  }
}
```

`params` 里的占位符会被替换成你界面里填的出发站、到达站、日期。
**参数名必须和供应商文档一致**（有的叫 `from_station`，有的叫 `start`，有的叫 `departStation`）。

3. 保存文件

## 第 4 步：用「测试连接」对齐字段（最关键）

供应商返回的 JSON 结构每家都不一样。点「**测试连接**」，会弹出一个窗口显示**原始返回**，像这样：

```json
{
  "result": {
    "list": [
      {"train_no": "G1722", "start_station": "武汉", "end_station": "南京南",
       "start_time": "08:00", "arrive_time": "10:30", "lishi": "02:30", "price": "200"}
    ]
  }
}
```

然后回去改配置里的两块：

| 配置项 | 作用 | 举例 |
|---|---|---|
| `records_path` | 车次列表在返回 JSON 里的位置（点号分隔） | `result.list` |
| `field_map` | 你的字段名 → 程序认的字段名 | `"code": "train_no"` |

完整对照：

```json
"records_path": "result.list",
"field_map": {
  "code":         "train_no",
  "from_station": "start_station",
  "to_station":   "end_station",
  "depart":       "start_time",
  "arrive":       "arrive_time",
  "duration":     "lishi",
  "price":        "price"
}
```

左边是程序要的 7 个字段（**不能改名**），右边填供应商返回里的实际字段名。

## 第 5 步：验证

1. 填出发站、到达站、日期
2. 点「**API 直连查询**」
3. 结果出现在表格里 → 选中一趟 →「加入路线 →」

如果报错，看提示：
- `API 还没配置` → url 或 key 没填
- `按 records_path=「xxx」没取到列表` → 路径写错了，回去看「测试连接」的原始返回
- `HTTP 401/403` → key 错了或没权限
- `HTTP 429` → 超出调用次数

## 费用与安全

- 价格以平台标价为准（个人按次用通常每月几元到几十元）。
- **Key 是明文存在 `api_config.json` 里的**，别把这个文件发给别人，也别提交到 GitHub。
- 如果泄露，去平台后台重置 key，改配置即可。

## 不配置会怎样

一切照旧：本地车次库（粘贴入库）继续可用，只是没有全自动查询。

## 留好的接口位置

| 文件 | 作用 |
|---|---|
| `train_api.py` | 适配器：构造请求（GET/POST）、取嵌套字段、映射成统一结构 |
| `api_config.json` | 你的配置（url / key / params / records_path / field_map） |

换供应商只改 json，不用动代码。

## 附：聚合数据（已实测接好）

2026-11-02 实测确认的接口信息：

| 项 | 值 |
|---|---|
| 接口地址 | `https://apis.juhe.cn/fapigw/train/query` |
| 文档 | https://www.juhe.cn/docs/api/id/817 |
| 必填参数 | `key`、`search_type=1`、`departure_station`、`arrival_station`、`date` |
| 日期限制 | **只能查 15 天内** |
| 返回列表位置 | `result`（**直接是数组**，不是 `result.list`） |
| 频率限制 | **每秒 1 次**（程序已自动限流 1.2 秒/次） |
| 票价结构 | `prices` 是数组，含商务座/一等座/二等座/无座，按 `seat_name` 取 |

已写进 `api_config.json` 的字段映射（**注意 `price` 用 `price_seat` 按坐席名取，不是取数组第一个**）：

```json
"records_path": "result",
"price_seat": "二等座",
"field_map": {
  "code":         "train_no",
  "from_station": "departure_station",
  "to_station":   "arrival_station",
  "depart":       "departure_time",
  "arrive":       "arrival_time",
  "duration":     "duration"
}
```

> 踩过的坑：一开始把 `price` 映射成 `prices.0.price`，结果抓到的是**商务座**（1145 元），
> 实际二等座只要 371 元。改成 `price_seat: "二等座"` 后正确。
> 想显示一等座就改成 `"price_seat": "一等座"`。

错误码对照（程序已内置成中文提示）：

| code | 含义 | 怎么办 |
|---|---|---|
| 10001 / 10002 | key 无效 | 去「我的API」确认 AppKey 属于火车票接口且已审核 |
| 10012 | 当日免费次数用完 | 明天再试或升级套餐 |
| 281701 | 查询失败 | 站名写错，或该日期无班次 |

> 注意：**接口地址和参数名来自公开文档与实际返回**，不是猜的。曾误写成 `apis.juhe.cn/train/s2s`，实测返回 404「接口地址不存在」，已更正。
